## 1. 개요

"Timer/COUNT 0, 2번"이라는 표현은 특정 제품명이 아니라, **AVR(ATmega) 계열 마이크로컨트롤러가 제공하는 8비트 타이머인 Timer/Counter0과 Timer/Counter2가 지원하는 4가지 동작 모드 중 0번과 2번**을 가리킵니다.

이 두 타이머는 레지스터 구조와 동작 원리가 사실상 동일하기 때문에 항상 "0, 2"로 함께 묶어 설명되며, Timer/Counter0,2는 Normal mode(counter), Clear Timer on Compare Match(CTC) mode와 2종류의 PWM(Pulse Width Modulation) mode를 지원한다는 점이 핵심입니다. 즉 전체 4개 모드 중:

- **0번 = Normal 모드**
- **1번 = Phase Correct PWM 모드**
- **2번 = CTC 모드**
- **3번 = Fast PWM 모드**

로 구성되어 있으며, 오늘 정리하는 내용은 이 중 0번과 2번입니다.

## 2. AVR Timer/Counter0, Timer/Counter2의 하드웨어 구조

- 둘 다 **8비트** 타이머로, 셀 수 있는 범위는 0~255입니다.
- ATmega128 계열 문서에 따르면 Timer/Counter1의 제어 비트 명칭에서 번호만 2로 바꾸면 Timer/Counter2의 제어 비트가 된다는 식으로, 사실상 이름만 다른 쌍둥이 타이머로 취급됩니다.
- 큰 차이점 하나: Timer/Counter2는 외부 클럭 소스(T2 핀)를 가지므로 Timer/Counter0와 달리 외부 클럭 소스 모드를 선택할 수 있다는 점입니다. 이 덕분에 Timer2는 흔히 **외부 크리스탈을 붙여 RTC(실시간 시계)용 비동기 타이머**로도 활용됩니다.

핵심 용어 정리:

| 용어 | 의미 |
|---|---|
| **BOTTOM** | 타이머가 가질 수 있는 최솟값 |
| **MAX** | 8비트 타이머가 가질 수 있는 최댓값 |
| **TOP** | 동작 모드에 따라 타이머가 실제로 도달하는 최댓값 (MAX일 수도, OCR 레지스터 값일 수도 있음) |
| **TCNT0/TCNT2** | 실시간 카운트 값이 저장되는 레지스터. 클럭이 들어올 때마다 1씩 증가(혹은 감소) |
| **OCR0/OCR2** | 출력 비교 레지스터. TCNT와 계속 비교되며, 일치 시 이벤트 발생 |

이 개념들은 TCNT는 클럭 입력마다 값을 1씩 증가 또는 감소시키는 타이머/카운터 레지스터이고, OCR은 TCNT와 계속 비교되어 일치 시 OC 단자에 신호를 출력할 수 있게 하는 출력 비교 레지스터라는 설명에 근거합니다.

## 3. 동작 모드를 결정하는 WGM 비트

모드 선택은 **WGM** 비트로 이루어집니다. WGM02:0(이 중 WGM02는 TCCR0B 레지스터에 있음)가 Timer/Counter의 동작 모드를 결정하며, 모드에 따라 서로 다른 파형(Waveform)이 발생한다는 것이 핵심 원리입니다.

구형 칩(ATmega128 등)은 TCCR0 레지스터 하나에, 신형 칩(ATmega328/2560 등)은 TCCR0A·TCCR0B 두 개로 나뉘어 있지만 원리는 같습니다.

## 4. 모드 0 — Normal 모드 상세

### 동작 원리
- TCNT0가 **0부터 255까지 단순 증가**만 반복합니다.
- 255를 초과하는 순간 **Overflow**가 발생하며 자동으로 0으로 되돌아갑니다.
- 이때 **Timer OVerflow 플래그**가 세팅되고, 인터럽트가 허용되어 있으면 **오버플로우 인터럽트**가 걸립니다.

0번 모드(Normal)는 일반적인 오버플로우 타이머 인터럽트 방식이라는 설명대로, 별도의 "목표값" 개념이 없고 그냥 0→255→0을 계속 반복하는 가장 단순한 형태입니다.

### 특징
- 구현이 가장 간단함 (레지스터 설정 최소화)
- 주기는 오직 **프리스케일러**로만 조절 가능 (0~255, 즉 256틱 고정)
- 정밀한 시간 제어보다는 "대략 일정 간격마다 뭔가 하고 싶다"는 용도에 적합

## 5. 모드 2 — CTC 모드 상세

### 동작 원리
- CTC는 **Clear Timer on Compare Match**의 약자입니다.
- TCNT0 값이 증가하다가, 미리 설정해 둔 **OCR0(A) 값과 일치**하는 순간:
  1. TCNT0이 **자동으로 0으로 리셋**됩니다.
  2. **Compare Match 인터럽트 플래그**가 세팅됩니다.

2번 모드(CTC)는 비교 일치 시 인터럽트가 발생하는 방식이며, 이름 그대로 "비교 일치가 나면 타이머를 지운다"는 동작이 그대로 구현되어 있습니다.

### 장점
- OCR0과 TCNT0이 일치하면 TCNT0이 자동으로 0이 되므로, 인터럽트 서비스 루틴(ISR)에서 별도로 초기화할 필요가 없다는 것이 큰 장점입니다.
- OCR0 값을 바꾸는 것만으로 **원하는 주기를 자유롭게(0~255 범위 내에서) 설정** 가능 — Normal 모드는 256틱 고정이지만 CTC는 가변적입니다.
- 16비트 타이머(Timer1 등)에서는 CTC 모드가 두 갈래로 더 세분화되는데, OCRnA 값과 TCNT 값이 일치할 때 인터럽트가 발생하는 4번 모드와, ICRn 레지스터 값과 일치할 때 발생하는 12번 모드로 나뉜다는 점도 참고할 만합니다.

### 활용
- 정확한 주기의 인터럽트가 필요한 경우 (예: 1ms마다 시스템 틱 발생, 특정 초 단위로 LED 토글)
- OC0 핀에 **CTC 기반 사각파(square wave)**를 직접 출력해 스피커 톤 생성, 클럭 신호 생성 등에도 사용

## 6. (참고) 모드 1, 3 — PWM 모드와의 비교

질문의 핵심은 0, 2번이지만 같은 계열의 1, 3번 모드도 함께 이해하면 전체 그림이 명확해집니다.

### 모드 1 — Phase Correct PWM
- WGM0[1:0]=01로 설정하면 선택되며, 듀얼 슬로프(dual slope) 방식으로 동작한다고 설명됩니다.
- TCNTn이 BOTTOM에서 MAX까지 증가했다가 다시 MAX에서 BOTTOM까지 감소하는 동작을 반복하며, 그 과정에서 계속 OCRn 값과 비교한다는 원리입니다.
- 대칭적인 파형이 나오기 때문에 모터 제어처럼 대칭적인 파형 생성이 중요한 분야에 CTC보다 Phase Correct PWM이 선호된다는 특징이 있습니다.

### 모드 3 — Fast PWM
- 단일 슬로프(single-slope, 0→TOP) 방식으로 카운트하며, 같은 조건이면 Phase Correct PWM보다 2배 높은 주파수를 낼 수 있다는 것이 핵심 차이입니다.
- 실측 예시로 동일한 12MHz 클럭·프리스케일러 8 조건에서 Phase Correct PWM은 약 2.942kHz, Fast PWM은 약 5.86kHz가 나와 정확히 2배 차이를 보였다는 실험 결과가 보고되어 있습니다.

### 0/2번(비-PWM)과 1/3번(PWM)의 근본적 차이
- 0, 2번은 **OC 핀에 물리적 파형을 낼 필요가 없는 경우** 사용 — 인터럽트만으로 내부 카운트/플래그 처리
- 1, 3번은 **OC 핀에 실제 듀티비를 가진 구형파(PWM)를 출력**해야 하는 경우 사용 — LED 밝기 조절, 모터 속도 제어, DAC 대용 등

## 7. 프리스케일러(Prescaler)

CPU 클럭은 매우 빠르기 때문에(예: 16MHz = 초당 1,600만 클럭), 이를 그대로 타이머에 넣으면 너무 짧은 시간 단위밖에 셀 수 없습니다. 이를 나눠 쓰는 것이 **프리스케일러**입니다.

- 설정 비트: `CS02:0` (TCCR0/TCCR0B 내)
- 일반적으로 선택 가능한 분주비: **1, 8, 64, 256, 1024**
- 예: 16MHz 클럭을 1024분주하면 타이머 클럭 주기는 약 64μs가 되어, 8비트(256틱) 기준 최대 약 16.4ms까지 하나의 오버플로우/비교일치 주기로 만들 수 있습니다.

## 8. 관련 레지스터 총정리

| 레지스터 | 역할 |
|---|---|
| **TCCR0(A/B)**, **TCCR2(A/B)** | 타이머 동작 모드(WGM), 출력 비교 모드(COM), 프리스케일러(CS) 설정 |
| **TCNT0**, **TCNT2** | 현재 카운트 값 저장 |
| **OCR0(A/B)**, **OCR2(A/B)** | 비교 기준값 저장 (CTC/PWM 모드에서 사용) |
| **TIMSK** | 각 타이머의 인터럽트 사용 여부(Overflow, Compare Match 등) 설정 |
| **TIFR** | 인터럽트 발생 여부를 나타내는 플래그 (읽고 쓰면 클리어) |
| **FOC0/FOC0A** | Force Output Compare — Non-PWM 모드에서만 동작하며, 이 비트에 1을 쓰면 실제 비교일치가 일어난 것과 동일한 신호를 파형 발생 유닛에 강제로 가할 수 있음 (단, 인터럽트는 발생시키지 않음) |

Compare Match 발생 시 물리적 핀(OC0 등)에 파형을 낼 필요가 없는 **일반적인 용도**에서는 굳이 파형을 토글하지 않고, 인터럽트가 걸릴 때마다 코드 내부의 flag나 count 변수로 처리하는 방식이 일반적이며, 이 경우 보통 COM 비트는 0,0으로 설정합니다.

## 9. 예제 코드

### 9-1. 모드 0 (Normal) 설정 예
```c
// WGM01=0, WGM00=0 → Normal 모드
// CS02:0 = 1,1,1 → 1024 분주
TCCR0 |= (0<<FOC0)|(0<<WGM01)|(0<<WGM00)|(0<<COM01)|(0<<COM00)
        |(1<<CS02)|(1<<CS01)|(1<<CS00);
```

### 9-2. 모드 2 (CTC) 설정 예 — 최신 스타일(TCCR0A/B 분리형)
```c
#include <avr/io.h>
#include <avr/interrupt.h>

void timer0_ctc_init(void) {
    TCCR0A |= (1 << WGM01);      // CTC 모드 선택
    OCR0A = 155;                  // 비교 기준값 설정 (원하는 주기)
    TCCR0B |= (1 << CS02) | (1 << CS00); // 1024 분주
    TIMSK0 |= (1 << OCIE0A);     // Compare Match A 인터럽트 허용
    sei();                        // 전역 인터럽트 허용
}

ISR(TIMER0_COMPA_vect) {
    // TCNT0은 자동으로 0으로 클리어되므로 별도 초기화 불필요
    // 여기에 주기적으로 실행할 코드 작성
}
```

### 9-3. Fast PWM(모드 3) 참고 예 — LED 밝기 제어
```c
// PWM 초기화: 비반전 모드, 프리스케일러 1
TCCR0 = (1<<WGM00) | (1<<WGM01) | (1<<COM01) | (1<<CS00);
DDRB |= (1<<PB3);   // OC0 핀 출력 설정

// duty 값을 0~255로 바꿔주면 LED 밝기가 변함
OCR0 = duty;
```
이 예제는 Fast PWM 모드와 비반전 출력을 설정한 뒤 OCR0 값을 점점 늘리거나 줄여 LED의 밝기를 서서히 조절하는 예제에서 착안한 구성입니다.

## 10. 실무 활용 사례

| 모드 | 대표 활용 사례 |
|---|---|
| **0 (Normal)** | 간단한 폴링용 지연, 대략적 주기의 태스크 스케줄링, 카운터로서 외부 이벤트 개수 세기 |
| **2 (CTC)** | 정밀 시스템 틱(RTOS tick) 생성, 정확한 1초 LED 점멸, 버저용 특정 주파수 사각파 출력, 다른 주변장치의 클럭 소스 생성 |
| **1 (Phase Correct PWM)** | 모터 속도 제어(대칭 파형 필요), 오디오 신호 합성 |
| **3 (Fast PWM)** | LED 밝기 제어, 고주파 스위칭이 필요한 전력 회로, DAC 대체 출력 |

## 11. 타 아키텍처와의 비교

### 11-1. 8051 계열 타이머와의 비교
8051도 개념적으로 유사한 타이머/카운터 구조를 갖고 있지만 세부 구현이 다릅니다.

- 8051은 Timer0과 Timer1이라는 두 개의 타이머/카운터를 가지며, TH0/TL0(또는 TH1/TL1)이라는 상위·하위 바이트 레지스터로 구성되고, TMOD와 TCON 레지스터로 타이머를 선택·제어한다는 점이 AVR과 다릅니다.
- C/T 비트로 타이머(내부 클럭 카운트)와 카운터(외부 이벤트 카운트) 동작을 전환하며, 8051의 타이머는 항상 카운트업(up)만 수행한다는 점도 특징입니다.
- 8051은 AVR처럼 WGM 비트로 세분화된 4가지 모드가 있는 게 아니라, 13비트 모드(모드0), 16비트 모드(모드1), 8비트 오토리로드 모드(모드2, 주로 시리얼 통신 보레이트 생성에 사용)로 나뉜다는 차이가 있습니다. 즉 8051의 "모드2"는 AVR의 CTC 모드와 이름은 같은 숫자여도 전혀 다른 개념(오토리로드)입니다. 혼동하지 않도록 주의가 필요합니다.

### 11-2. STM32(ARM Cortex-M) 타이머와의 비교
AVR의 8비트 타이머 개념이 좀 더 발전된 형태가 ARM 기반 STM32 타이머입니다.

- STM32는 시간 기반 생성용 기본 타이머(TIM6/7), 1~4개의 입출력 채널을 가진 범용 타이머(TIM2~5, 9~11) 등으로 세분화되어 있으며, 출력 비교·원펄스 모드·입력 캡처·엔코더 인터페이스 등 다양한 기능을 지원한다는 점에서 AVR 8비트 타이머보다 훨씬 다기능입니다.
- 카운트 방식도 유사하게 Up, Down, Up/Down(중앙 정렬) 모드를 지원하는데, AVR의 Normal(0→255→0)과 STM32의 Up 모드가 개념적으로 대응됩니다.
- 다만 STM32는 16/32비트 폭, 다중 채널 캡처/비교, DMA 연동 등 AVR 8비트 타이머보다 구조가 훨씬 복잡하고 유연합니다.

### 11-3. 최신 AVR(tinyAVR/AVR Dx 시리즈)의 TCA·TCD와 비교
전통적인 ATmega의 Timer0/2 구조는 최신 AVR 제품군에서 TCA, TCB, TCD 등으로 재편되었습니다.

- **TCA(Timer/Counter type A)**: PWM 신호 생성에 최적화된 타이머로, 16비트 단일 모드 또는 8비트 두 개로 분할해서 사용할 수 있으며 TOP까지 증가 후 BOTTOM으로 리셋되는 것이 기본 동작(단, 듀얼 슬로프 모드에서는 감소도 함)이라는 점에서 기존 Normal/CTC/PWM 개념을 계승합니다.
- **TCD(Timer/Counter type D)**: 하프 브리지·풀 브리지 같은 복잡한 PWM 파형 생성에 최적화된 12비트 타이머로, 싱글 램프·듀얼 램프·쿼드 램프·듀얼 슬로프의 4가지 동작 모드를 지원합니다. 이는 기존 8비트 Timer0/2보다 훨씬 정교한 모터 제어용 파형까지 다룰 수 있게 확장된 형태입니다.

## 12. 전체 비교표 및 요약

| 항목 | 모드 0 (Normal) | 모드 2 (CTC) |
|---|---|---|
| 카운트 범위 | 0 → 255 고정 | 0 → OCR0 값 (가변) |
| 리셋(Clear) 시점 | 255 초과 시 자동 (오버플로우) | OCR0 값과 일치 시 자동 |
| 주요 인터럽트 | Overflow (TOV) | Compare Match (OCF) |
| 주기 조절 방법 | 프리스케일러만 | 프리스케일러 + OCR0 값 |
| ISR에서 재초기화 필요 여부 | 필요 없음 (자동 오버플로우) | 필요 없음 (자동 클리어) |
| 대표 용도 | 단순 반복 인터럽트, 이벤트 카운팅 | 정밀 주기 생성, 사각파 출력 |
| 물리 핀 출력 | 기본적으로 사용 안 함 | 기본적으로 사용 안 함 (필요 시 OC 토글 가능) |

**핵심 요약**
- 0번(Normal)과 2번(CTC)은 둘 다 **PWM처럼 핀에 파형을 낼 필요가 없는 "비-PWM(non-PWM)" 모드**로, 순수하게 인터럽트/카운팅 목적에 최적화되어 있습니다.
- 차이는 **"언제, 어떤 값에서 타이머가 리셋되고 인터럽트가 걸리는가"**입니다: Normal은 고정된 255에서, CTC는 사용자가 지정한 OCR0 값에서 리셋됩니다.
- 더 정밀하고 유연한 주기 제어가 필요하면 CTC(2번)를, 가장 단순한 반복 인터럽트만 필요하면 Normal(0번)을 선택하는 것이 일반적인 기준입니다.

# PSD 거리 센서 필터링 적용 보고서
### GP2Y0A02YK0F 적외선 거리 센서 – 중앙값(Median) 필터 적용

## 1. 개요

본 보고서는 적외선 거리 센서 GP2Y0A02YK0F(PSD 센서)로부터 ADC 값을 읽어 거리로 환산하는 과정에서, 센서 출력이 순간적으로 튀는 노이즈(스파이크)를 제거하기 위해 적용한 중앙값(Median) 필터에 대해 정리한 것이다. 센서의 원리상 20cm 미만 구간에서는 전압-거리 관계가 반전되어 하나의 ADC 값이 두 개의 거리를 가리키므로, 이 구간은 계산을 포기하고 경고만 출력하도록 하였으며, 그 외 구간(20~150cm)에 대해서만 필터링 및 거리 환산을 수행한다.

## 2. 사용한 필터의 개념

### 2-1. 중앙값 필터(Median Filter)란

중앙값 필터는 최근 N개의 샘플을 크기순으로 정렬한 뒤, 그 중앙에 위치한 값을 대표값으로 취하는 비선형 필터이다. 본 코드에서는 20ms 주기로 ADC 값을 5개(MEDIAN_N = 5) 모은 뒤, 삽입정렬(Insertion Sort)로 정렬하고 그 중 3번째 값(buf[n/2])을 최종 ADC 값으로 사용한다.

동작 절차는 다음과 같다.

- ① 20ms마다 ADC를 1회 읽어 5칸짜리 샘플 배열에 순환 저장(idx는 0~4를 순환)
- ② 200ms 출력 주기가 되면, 그동안 모인 5개의 샘플을 삽입정렬
- ③ 정렬된 5개 값 중 가운데(인덱스 2) 값을 최종 ADC 값으로 채택
- ④ 채택된 값을 룩업테이블(psd_lut) 기반 선형보간으로 거리(0.1cm 단위)로 환산

```c
buf[n/2]  //정렬 후 중앙값 = 5개 중 3번째 값 반환
```

## 3. 필터의 특징

### 3-1. 장점

- **스파이크(순간적으로 튀는 이상값) 제거에 효과적**: 평균 필터와 달리 이상값이 결과 계산에 전혀 반영되지 않고 그대로 버려진다.
- **구현이 간단하고 연산량이 적다**: 샘플 수가 5개로 고정되어 있어 삽입정렬만으로 충분하며, 부동소수점 연산 없이 정수 연산만으로 처리 가능해 8비트 AVR에서도 부담이 없다.
- **경계값(에지) 보존**: 저역통과(이동평균) 필터처럼 값의 변화 구간을 뭉개지 않고, 실제 거리가 바뀌면 비교적 빠르게 새 값으로 수렴한다.

### 3-2. 단점 및 한계

- **지연(latency) 발생**: 5개 샘플이 모두 채워질 때까지(약 100ms) 결과를 낼 수 없으며, 매 주기 최신값이 아닌 과거 구간의 대표값을 사용하므로 실시간성이 이동평균만큼 요구되는 경우 불리할 수 있다.
- **연속으로 여러 번 튀는 노이즈에는 취약**: 5개 중 3개 이상이 동시에 튀면 중앙값 자체가 오염된다. 즉 '이상값의 개수가 전체 샘플의 과반 미만'이라는 전제가 필요하다.
- **평균 필터와 달리 노이즈를 '섞어서 완만하게' 만드는 것이 아니라 통째로 버리는 방식**이므로, 완만한 잡음(백색 잡음처럼 지속적으로 흔들리는 잡음)을 줄이는 효과는 이동평균보다 작다.

## 4. 필터 미적용 값과 필터 적용 값의 변화

아래는 정상적인 거리(약 50~60cm에 해당하는 ADC 200대) 측정 중, 센서 노이즈나 순간적인 반사광 등으로 인해 4번째와 11번째 샘플에서 ADC 값이 600 부근으로 튀었다고 가정한 예시 데이터이다. 필터 미적용 시에는 이 값이 그대로 출력에 반영되지만, 5개 중앙값 필터를 적용하면 해당 스파이크가 결과에서 제외되는 것을 확인할 수 있다.

| 샘플 순번 | 원본 ADC 값 (필터 미적용) | 중앙값 필터 적용 후 ADC 값 | 비고 |
|---|---|---|---|
| 0 | 230 | - | - |
| 1 | 232 | - | - |
| 2 | 229 | - | - |
| 3 | 231 | - | - |
| 4 | **600** | 231 | 스파이크 제거됨 |
| 5 | 233 | 232 | |
| 6 | 235 | 233 | |
| 7 | 230 | 233 | |
| 8 | 228 | 233 | |
| 9 | 231 | 231 | |
| 10 | 229 | 230 | |
| 11 | **610** | 230 | 스파이크 제거됨 |
| 12 | 232 | 231 | |
| 13 | 234 | 232 | |
| 14 | 231 | 232 | |

이 스파이크가 실제로 어떤 의미를 갖는지, 코드의 판정 로직(Psd_AdcToDist)을 기준으로 비교하면 다음과 같다.

| 구분 | 필터 미적용 | 중앙값 필터 적용 |
|---|---|---|
| 4번 샘플 ADC 값 | 600 (스파이크 그대로 출력) | 231 (스파이크 제거, 정상값 유지) |
| 환산 거리 / 상태 | ADC 600 > 512 → PSD_TOO_CLOSE, "20cm 미만" 오경고 발생 | 약 51.7cm, PSD_OK 정상 거리값 출력 |
| 출력 안정성 | 센서 노이즈 한 번에 통신 라인에 엉뚱한 경고 문자열이 그대로 나감 | 5개 중 중앙값만 취하므로 한 번의 튐은 결과에 반영 안 됨 |

즉, 필터를 적용하지 않았다면 실제로는 물체가 약 51.7cm 거리에 안정적으로 있음에도 불구하고, ADC 값이 512(ADC_NEAR_LIMIT)를 순간적으로 넘어서면서 "[WARN] too close (<20cm)"라는 잘못된 경고가 UART로 그대로 송출되었을 것이다. 중앙값 필터를 적용한 결과, 이러한 순간적 튐은 최종 출력에 반영되지 않고 실제 거리에 가까운 안정된 값(ADC 약 230~233, 거리 약 50~52cm)만 출력되었다.

## 5. 결론

PSD 센서는 특성상 반사광 세기나 표면 재질에 따라 순간적으로 값이 튀는 경우가 있는데, 이를 필터링 없이 그대로 사용하면 실제로는 정상 범위인 상황에서도 '센서 미연결', '측정 불가(20cm 미만)' 등의 잘못된 상태 판정이 발생할 수 있다. 본 코드에서 사용한 5개 샘플 중앙값 필터는 적은 연산량으로 이러한 순간적 스파이크를 효과적으로 제거하면서도, 실제 거리 변화에는 비교적 빠르게 반응할 수 있어 임베디드 환경에서 실시간 거리 표시용으로 적합한 필터라 판단된다. 다만 연속적으로 여러 샘플이 동시에 튀는 상황에는 대응이 어려우므로, 필요 시 이동평균 필터나 이상치 임계값 검사와 병행하는 방안을 추가로 고려할 수 있다.
